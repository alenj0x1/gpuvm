## The window

- **Sidebar:** every Hyper-V VM on the PC, created with GpuVM or not, with its state (or the current step of a running job). It can be collapsed. **Create machine** is at the end of the list.
- **Main area:** the selected VM: header with its state, edition, GPU and profile; notices; live stats; usage chart; and options.
- **Library** is the layers icon in the title bar: your profiles, templates, disks, shared disks and ISOs. See [Library](#library).
- **Preferences** is the gear icon in the title bar, next to the light/dark toggle. See [Preferences](#preferences).

GpuVM opens without administrator rights; the **GpuVM** Windows service does the Hyper-V work for it. If the service is stopped and set to **Manual**, the app says so with a **Start service** button. If the service is missing, it says so with a **Repair** button that registers it again after a UAC prompt. Deleting a machine, a disk, a shared disk or a template asks for a UAC confirmation first; if you say no, nothing is deleted. If Hyper-V can't be read, a notice shows the error with **Retry**.

## Home

The app opens on **Home**, the first item in the sidebar:

- **The last machine you opened**, with **Open** or **Start and open**.
- **Memory**: how much the PC has free, what is using the most, and each machine marked **On**, **Can start** or with how much memory it is missing. A machine that doesn't fit offers to open with the memory that does fit, for example **Open with 6 GB**: it lowers its memory to what fits (saved, like changing it in Options) and opens it. The machine's own page shows the same.
- **What needs attention**, only when there is something: a GPU driver out of date, Moonlight not paired, apps waiting to be installed, the Windows password missing or little disk space left, each with the button that fixes it.

## Create a VM

With no VMs yet, the app invites you to create the first one.

<Image src={emptyLight} alt="Empty state inviting you to create the first machine" />

<Steps>

1. Click **Create machine**.

2. Fill in the form:
   - **Name**: letters, numbers, `_` or hyphens, up to 40 characters, no spaces. It suggests `win-gpu`.
   - **Install Windows** / **From a template**, when you have [templates](#templates): from a template the VM is ready in seconds and only asks for the name and profile; Windows, its apps, cleanup level and password come from the template.
   - **Windows image**: the ISOs you already used or added first, then the ones found in your Downloads and Desktop folders, or **Browse for another ISO**.
   - **Profile**: **Balanced** (`balanced`), **Maximum performance** (`max-performance`, the default) or one of your own from the [Library](#library). The profile fills in the rest, including its ISO, apps and use. See [Profiles](/gpuvm/docs/profiles/).
   - **Windows**: how clean Windows is. See [Windows](#windows).
   - **Apps to install**: installed the first time the VM opens. See [Apps](#apps).
   - **Windows password** for the local user `gpuvm`, at least 6 characters, typed twice.

   **Create machine** stays disabled until the form is complete; any problem shows next to its field as you type.

3. Click **Create machine**. The dialog shows each step as it happens. You can close it: the progress stays in the sidebar, and if creation fails the dialog opens again with the error.

4. When it's done the new VM opens in the app and starts. Windows finishes setting itself up on its own in a few minutes.

</Steps>

## Start and open

The main button changes with the VM's state:

| State | Button | What it does |
|---|---|---|
| Off | **Start and open** | Starts the VM and opens it in Moonlight. |
| Running | **Open** | Opens it in Moonlight. |
| Paused | **Resume** | Resumes the VM. |
| Not created with GpuVM | **Start** / **Console** | Starts it / opens the Hyper-V console. |

**Start and open** leaves everything ready on its own, and the button shows each step while it works:

1. If the VM is off and the host's GPU driver changed, it copies the new driver into the VM first (avoids a black screen or error code 43).
2. Starts the VM and waits for Windows (the first time, Windows finishes its setup) and for Sunshine.
3. Returns the Windows session to the GPU display if it was taken somewhere else.
4. Sets the VM's display to the Moonlight resolution and frame rate, and makes Sunshine capture it.
5. Installs gamepad support and the administrator prompt watcher the first time.
6. Pairs Moonlight with Sunshine if this PC isn't paired yet.
7. Opens Moonlight and waits until the picture shows.

Work that lasts until Windows restarts (the display, the capture mode, the sound) is done once per boot, through one connection to the VM. Opening a VM that is already on takes about 7 to 10 seconds until you see the picture; from off, about a minute, most of it Windows and Sunshine starting. The button stays busy until the picture is there, so the VM can't be opened twice: clicking **Open** again while Moonlight already shows it brings that Moonlight window to the front. If the VM is off, saved or paused while GpuVM waits for its network address, it says so at once instead of waiting.

Warnings along the way (for example, audio not configured yet) appear as notifications.

## Keyboard, mouse and gamepads

With Moonlight in fullscreen, **Alt+F4**, **Alt+Tab** and the **Windows key** go to the VM instead of closing Moonlight or taking you back to this PC. To quit the stream, press **Ctrl+Alt+Shift+Q**.

Gamepads work too: GpuVM installs the virtual gamepad driver (ViGEmBus) in the VM, and a controller connected to this PC reaches Windows in the VM as an Xbox 360 controller.

From a key, click, mouse move or gamepad button on this PC to the change in Moonlight's picture takes about 17 ms (median) at 120 FPS or more, about 11 ms more than the same PC without streaming. At 60 FPS it adds one more frame.

## Administrator prompts

With the **Fast** capture (the default), Windows' administrator prompts (UAC) inside the VM can't be streamed: Windows draws them on a separate, protected desktop. GpuVM shows them instead: while one is open, a small card appears over everything, Moonlight included, with the machine, the program asking and its publisher (**Unknown publisher** when it isn't signed). **Allow** and **Deny** answer it in the VM.

- Only this PC can answer: a program inside the VM can't approve itself.
- If a different prompt opened in the meantime, nothing is pressed and the card shows the new one.
- It needs the VM's [guest password](#guest-password-banner).
- With the **Classic** capture the prompts show in Moonlight as usual and the card doesn't appear. See [Capture modes](/gpuvm/docs/streaming/#capture-modes).

## Paste into the VM

While the VM is running, the clipboard button next to the **⋯** menu, **Paste into the VM**, copies the text you copied on this PC to the VM's clipboard, ready for Ctrl+V. It only goes from the PC to the VM: the VM never reads this PC's clipboard. It needs the [guest password](#guest-password-banner).

## Live stats

Four cards, refreshed every 2 seconds while a VM is on (every 6 seconds otherwise):

- **Processor**: threads and % in use.
- **Memory**: fixed memory and how much is in use.
- **GPU**: % in use while running, or the share assigned to the VM while off; below, the GPU name.
- **Uptime**: time since start and the VM's IP address.

The **Usage** chart plots CPU and GPU over the last 5 minutes.

## Windows

The **Windows** card sets how clean Windows is inside the VM. Each level includes the previous ones:

- **Normal**: Windows as it comes.
- **Privacy**: diagnostic data at the minimum the edition allows (on Pro, Windows doesn't go below "Required"), no advertising ID, activity history, suggestions, Spotlight, Bing in Start, Copilot or Recall.
- **No extra apps**: also removes preinstalled apps (News, Weather, Solitaire, Clipchamp, personal Teams, the new Outlook...), also for new users, plus OneDrive and widgets. They can be installed again from Microsoft Store.
- **Minimal**: also turns off the telemetry and error reporting services and services a VM doesn't use (maps, location, fax, demo mode), and keeps Store apps from running in the background.

Choose a level and click **Apply**, or **Start and apply** if the VM is off. A lower level undoes the settings of the higher ones. Microsoft Defender, Windows Update, SmartScreen, UAC, the firewall, Microsoft Store and Xbox are never touched. You can also choose the level when creating the machine or in a profile; it is applied on Windows' first sign-in.

## Apps

The **Apps** card installs game launchers (Steam, Epic Games, Battle.net, EA app, GOG Galaxy, Ubisoft Connect), browsers (Chrome, Brave, Firefox), media (VLC, OBS Studio, Spotify), Discord, 7-Zip, WinRAR and Proton VPN in the VM. Search them or filter by category, then choose them and click **Install**, or **Start and install** if the VM is off. You can also choose them when creating the machine; they are installed the first time it opens. Each installer is downloaded inside the VM and only runs if Windows confirms it is signed by its publisher; pinned versions are also checked by SHA-256. The card needs the [guest password](#guest-password-banner).

## Options

For VMs created with GpuVM:

- **Processor:** threads, from 2 up to the host's threads minus one.
- **Memory:** GB, from 4 up to the host's memory minus 4 GB.
- **GPU for the VM:** 10–100 %, in steps of 10.
- **Disk:** grows the disk (it can't shrink). A fixed disk needs that much free space on the host. The VM's C: drive grows on its own the next time it opens.
- **Use:** what the machine is for. Each use sets the frame rate, V-Sync, frame pacing and mouse below; changing any of them by hand shows that the settings are custom.

  | Use | Frame rate | V-Sync | Frame pacing | Mouse |
  |---|---|---|---|---|
  | **Games** | Monitor | On | Off | For games |
  | **Movies and video** | 60 FPS | On | On | Free |
  | **Work** | Monitor | On | Off | Free |

- **Moonlight:** resolution (720p, 1080p, 1440p, 2160p), frame rate (30, 60, 120, 144 FPS or **Monitor**) and **Fullscreen** or **Window** (the size of the chosen resolution). **Monitor** streams at the refresh rate of the monitor you open the VM on, read every time it opens; GpuVM adds that rate to the VM's virtual display when it lacks it. At the monitor's own rate V-Sync adds no latency and stutters halve. New machines use it.
- **V-Sync:** **Whole picture** (on) shows every frame complete on the monitor; **Faster** (off) shows each frame as soon as it arrives, even if the monitor is halfway through drawing the previous one (tearing).
- **Frame pacing:** **Even** spreads the frames at a steady rhythm, best at 60 FPS; **Instant** shows each frame as soon as it's ready. Only with V-Sync on.
- **Capture:** how Sunshine captures the screen.
  - **Fast** (the default): the picture shows about 2.6 s after connecting, and games in exclusive fullscreen show too. Windows' administrator prompts are answered from GpuVM ([Administrator prompts](#administrator-prompts)).
  - **Classic**: administrator prompts show in Moonlight, but the picture can stay black for a while after connecting and games in exclusive fullscreen look black. See [Streaming](/gpuvm/docs/streaming/#capture-modes).
- **Network:**
  - **Internet only** (the default): the VM reaches neither this PC nor your local network, except for what the stream needs. The rules live on the VM's virtual switch port, outside the VM, so an infected VM can't remove them.
  - **Internet and local network**: the VM reaches this PC and the rest of your network. Use it only when you need it, for example for a NAS.
- **Advanced** (click to show):
  - **Mouse:** **For games** (the VM takes the mouse, as games need to turn the camera) or **Free** (the pointer moves in and out of the window as in remote desktop; most games don't work with it).
  - **Codec:** **Automatic** (Moonlight picks the best one this PC can show), H.264, HEVC or AV1. If the picture doesn't show, go back to **Automatic**.
  - **Image quality:** the bitrate in Mbps, up to 150. Higher uses more network; at the minimum, Moonlight picks it from the resolution and frame rate.

Moonlight, use, capture and network settings are saved without stopping the VM: Moonlight's apply the next time you open it, the capture right away if the VM is running (it restarts Sunshine), and the network right away. Processor, memory, GPU and disk need the VM off: if it's running the button reads **Shut down and apply**, which validates, shuts the VM down, applies and starts it again. If it can't start again (for example, not enough free memory), the previous settings are restored.

## Guest password banner

If GpuVM doesn't have the VM's Windows password (for example, after rebuilding the VM's state with `repair`), the VM shows a banner asking for it, for user `gpuvm`. It is saved encrypted with DPAPI and lets GpuVM fix things inside the VM through PowerShell Direct (without network and without asking you): waiting for setup to finish, moving the session back to the GPU display, setting the display resolution, installing gamepad support and answering administrator prompts. VMs created from the app already have it.

## Driver notice

If the VM's NVIDIA driver differs from the host's, a notice says so. It updates on its own the next time you start the VM from the app, or right away with **Update now** or **Shut down and update**.

## Power actions and more

The **⋯** menu has:

- **Start without opening**.
- **Shut down** (orderly), **Turn off** (click twice to confirm; unsaved work is lost), **Restart**, **Pause** / **Resume**.
- **Hyper-V console**. It only shows the basic Hyper-V display, not what the GPU draws.
- **Pair Moonlight again**.
- **Update GPU driver**, or **Shut down and update driver** if it's running.
- **Create template**, or **Shut down and create template** if it's running: saves this VM's Windows as a [template](#templates). The VM stays as it is and starts again afterwards.
- **Another pattern**: changes the VM's icon (an animal or object on its color) and its color. Clicking the pattern next to the VM's name (or a profile's) does the same; the new one shows everywhere at once.
- **Delete machine**: removes the VM from Hyper-V, keeping the `.vhdx` disk or deleting it too, after a UAC confirmation. It can't be undone.

<Aside type="caution">
Don't use Remote Desktop while streaming: it takes the console session away from the GPU display.
</Aside>

## Library

**Library**, the layers icon in the title bar, has five tabs:

- **Profiles**: the built-in profiles (marked **Built-in**) and your own. **New profile** or **Duplicate** starts one from another; yours can also be edited and deleted (click again to confirm). Each keeps processor, memory, GPU share, disk size and type (**Fixed** / **Dynamic**), Windows image, apps to install, the use and how Moonlight opens (resolution, frame rate, fullscreen or window), on top of the built-in profile it is **Based on**. **Create machine** fills everything in from the chosen profile.
- **Templates**: see [Templates](#templates).
- **Disks**: the disks in the GpuVM folder, which VM uses each one (**In use** or **Free**) and the free space on the PC. **Create machine with this disk** creates a VM again from a disk kept when its VM was deleted, with Windows and its apps as they were; free disks can be deleted (click again to confirm, then a UAC prompt; it can't be undone).
- **Shared**: see [Shared disks](#shared-disks).
- **ISOs**: the Windows images you used, with the machines that used them, plus the ones in Downloads and Desktop. **Add ISO** or **Add to the list** remembers one, and **Remove from the list** forgets it without deleting the file. Remembered ISOs are offered first in **Create machine**.

## Templates

A template is a VM's Windows saved as a read-only base disk, with its apps, cleanup level and password. Create one from a VM's **⋯** menu (**Create template**). A VM created **From a template** gets a disk on top of it that only stores what changes, so it is ready in seconds and takes a few GB. Each copy gets its own streaming identity (Moonlight pairs with it as a new host) and its own computer name. Its disk has the template's size and can't be enlarged.

The **Templates** tab lists each template with the VM it came from, its size and the machines built on it. **Create machine** opens the dialog with that template chosen. A template can only be deleted when no machine is built on it.

## Shared disks

A shared disk keeps your games or files apart from Windows and moves between machines, so a new VM doesn't download everything again. In the **Shared** tab, **New disk** asks for a name, a use (**Games** or **General**) and a maximum size; it only takes on the PC what you store on it.

- **Connect it** from the VM's **Shared disks** card: **Connect**, also while the VM runs. Inside, it gets a drive letter. A **Games** disk gets `SteamLibrary`, added to Steam's libraries (GpuVM closes Steam, adds it and opens it again; if a game keeps Steam open, it says so). **Disconnect** closes it inside Windows first; if a program is using it, it tells you instead. A disk attached to another machine that is off can be moved with **Bring from**.
- **Import folder** copies a folder of this PC into the disk, with its progress on the button. A Steam library brings only its games (`steamapps`). It works while the disk isn't attached to a running VM. GpuVM's own folders, Windows and folders that contain them (such as a drive or the Users folder) can't be imported.

<Aside type="note">
The copy only goes from this PC to the disk. Before writing, GpuVM checks that the disk has no links anywhere it would write (a VM could have left one to redirect the copy out of the disk); if it finds one, or a folder it can't check, it doesn't copy. A disk another machine wrote can still hold files that machine left: treat it like any disk you plug in.
</Aside>

## Preferences

<Image src={preferencesDark} alt="Preferences screen with the theme and close-window options, dark theme" />

- **Theme**: **System** (the default: follows Windows), **Light** or **Dark**. The sun/moon button in the title bar switches between light and dark directly.
- **When closing the window**:
  - **Quit completely** (the default): closing the window exits GpuVM.
  - **Stay in the tray**: closing the window hides it and GpuVM keeps running next to the clock, so jobs in progress continue. The tray icon's menu has **Open GpuVM** and **Quit**; a left click on it opens the window again.
- **When quitting GpuVM**:
  - **Keep them running** (the default): the machines keep running after GpuVM quits.
  - **Shut them down**: quitting GpuVM shuts down every running GpuVM machine cleanly, like the Start menu inside Windows, and frees its memory. GpuVM closes at once; the shutdown continues in the background.
- **GpuVM service**, the Windows service that does the Hyper-V work for the app:
  - **With GpuVM** (the default): it starts when GpuVM opens and stops when it quits, once what it was doing is finished (shutting the machines down, a machine being created).
  - **With Windows**: it starts with Windows.
  - **Manual**: it only starts and stops with the **Start** and **Stop** buttons here.
  - Switching to or from **With Windows** asks for a UAC confirmation, because it changes the service's settings in Windows. Starting and stopping it doesn't. The row below shows its state.

GpuVM runs as a single instance: opening it again (for example from the Start menu while it's in the tray) shows the window that is already open.
