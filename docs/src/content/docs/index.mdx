GpuVM creates Windows 10 and 11 virtual machines that use your PC's GPU, with the best performance each backend allows, shows them in its own viewer, and lets AI agents work in them while you watch.

<Shot name="home" alt="GpuVM's Home: a machine as a hologram inside its glass cube on a world of blocks, with its usage beside it and the other machines below" />

## Why

A regular Hyper-V VM only gets a basic display adapter, so games and GPU apps don't run well inside it. Hyper-V **GPU partitioning (GPU-P)** shares the host GPU with the VM, but setting it up by hand means copying driver files, tuning the VM and finding a way to actually *see* what the GPU draws, because the Hyper-V console only shows the basic Hyper-V display. GpuVM does all of that for you and keeps it working, on every edition of Windows 10 and 11: where Windows has no Hyper-V (Windows Home, for example), it runs the machine through Windows' Host Compute Service and shares the GPU the same way.

## How it works

<Steps>

1. **Create the VM.** GpuVM checks the host, applies the Windows edition from your ISO straight to a VHDX (without going through the installer), copies the host GPU driver into the guest and leaves an unattended setup: local account, no OOBE screens, Remote Desktop enabled and autologon. On Hyper-V the VM is Generation 2 with Secure Boot and TPM, so Windows 11 installs without tricks, and gets the profile's CPU, fixed memory, MMIO space, no checkpoints and the GPU partition. Without Hyper-V, GpuVM's service creates the machine through the Host Compute Service (UEFI with Secure Boot, the profile's CPU and fixed memory, and the GPU partition) and installs GpuVM's agent into its disk before the first boot, so GpuVM can reach Windows inside it.

2. **First boot.** Inside the VM, the guest setup script applies the profile's optimizations, installs the streaming components (Sunshine, a virtual display and GpuVM's own USB speaker for audio) and deletes `unattend.xml`, which holds the password. The VM then restarts once on its own.

3. **Start and open.** One click starts the VM, syncs the GPU driver if the host's changed, waits for Windows and Sunshine, fixes the session and the display, pairs GpuVM's viewer automatically and opens the stream inside the app, by default at your monitor's refresh rate. A VM that is already on shows its picture in about 7 to 10 seconds.

4. **Use it.** You use the VM in GpuVM's viewer, inside the app or full screen, with the image the GPU renders, your keyboard, mouse and gamepads, about 11 ms behind playing locally at 120 FPS or more. Windows' administrator prompts in the VM are answered from GpuVM, over the picture. Drop files on the picture, take screenshots and recordings, and save restore points to go back to; the app shows live CPU, memory and GPU usage.

</Steps>

## What's inside

<CardGrid>
  <Card title="Desktop app" icon="laptop">
    Tauri 2 + React, in English and Spanish, without administrator rights; a Windows service runs the machines. Every VM on the PC grouped in spaces, one-click start and open, each machine as a hologram in a glass cube you can decorate, a use per machine (games, movies, work), live usage, options, restore points, disposable machines, export and import, and a Library of profiles, templates, shared disks and ISOs. See [Using the app](/docs/using-the-app/).
  </Card>
  <Card title="PowerShell module and CLI" icon="seti:powershell">
    The `GpuVM` module (PowerShell 7) does the work; `gpuvm.ps1` exposes it as short commands.
  </Card>
  <Card title="Streaming" icon="rocket">
    GpuVM's own Sunshine inside the VM, a virtual display drawn by the GPU at your monitor's refresh rate, GpuVM's own USB speaker for audio, gamepads, and GpuVM's own viewer on the host, built on Moonlight, with a side panel of widgets.
  </Card>
  <Card title="Agents" icon="puzzle">
    GpuVM is an MCP server: Claude Code or any MCP client works in a disposable Windows machine while you watch and take control at any time. See [Agents](/docs/agents/).
  </Card>
  <Card title="Profiles" icon="setting">
    JSON profiles with inheritance that set the VM, the GPU share, streaming and Windows optimizations. See [Profiles](/docs/profiles/).
  </Card>
</CardGrid>

GpuVM has two backends and picks one on its own: **Hyper-V GPU-P** (`hyperv-gpup`) where Windows has Hyper-V, and the **Host Compute Service** (`hcs`) everywhere else, Home included, which only needs Windows' Virtual Machine Platform. In both, the GPU is shared between the host and the VM, and the guest uses the same driver as the host. New backends can be added; see [Architecture](/docs/architecture/#backends).
